## 二、ZySoulBot 当前架构与核心机制全景（截至 commit `39ab477`）

### 2.1 产品定位与核心铁律
- **定位**：开源、多角色、单机可自托管的 QQ 数字灵魂陪伴框架（首个内置示例人设包为纳西妲，但框架完全角色无关，支持同时挂载多个独立灵魂）。
- **核心目标**：不是“问答助手”或“任务执行器”，而是构建一个**有昼夜精力、真实情绪起伏、会记仇也会被哄好、有自己日常与心事、且能主动探索外部世界（查资料/写小工具/唱歌）的活人感数字生命**。
- **四条架构铁律**：
  1. **灵魂是资产**：每个角色由独立的人设包（`persona-pack`）+ 单文件 SQLite（`soul.db`，WAL + FTS5）+ Markdown 日记本 + 沙箱工作区 + 媒体库组成；底层 LLM 与聊天平台（OneBot11 等）均可无缝替换。
  2. **只给事实，不教做事**：身心、关系、记忆引擎绝不向对话 Prompt 塞“你现在应该冷淡回复/你应该安慰他”这类行为命令，也不做机械改写；只把客观事实和当事经历放入动态上下文，让角色人设自行决定反应，同时配合真实的机制后果（如忙时不秒回、冷淡时不主动找聊）。
  3. **纯领域核心隔离**：`src/soul/` 与 `src/shared/` 零循环依赖（由 `dependency-cruiser` 强门禁保证），不依赖任何具体 LLM SDK、数据库驱动或聊天平台框架。
  4. **Token 经济学前置**：长期 24/7 运行由个人买单，每一类后台思考与工具调用都受前缀缓存、折叠与每日预算约束。

### 2.2 灵魂原生轻量 Agent Loop（手脑合一）与 Token 策略
我们放弃了早期“主对话模型 + 独立 CLI Agent 子进程”的双脑方案（存在双重记忆割裂与工具输出 Token 爆炸），改为直接在 OpenAI 兼容 Chat Completions 上运行原生 `while (tool_calls)` 循环：
- **严格「静前动后」三明治消息结构**：
  - 前缀：`[Static System Prompt（人设核心，字节级锁定）]` + `[按块滑动的对话历史（满 30 条一次裁掉最老 10 条并锚定 1 条 summary，避免每轮滑窗击穿前缀缓存）]`
  - 尾部：`[当下动态事实块：时间 / 身心状态 / 关系与未解心结 / 按需召回的记忆与世界书片段]` + `[本轮用户输入]`
  - 实测在阿里云百炼 `deepseek-v4.1-flash` 上 Prefix Cache 命中率稳定在 **91%–93%**。
- **回合级脏工具折叠**：网页正文、搜索结果、脚本 stdout 仅在当前回合推理可见（截断 ≤ 2500 字），回合落库只保留极简一行 `foldSummary`（如 `查网页：今日北京多云 18°C`），后续轮次绝不重复计费。
- **后处理门控 + 单次六合一抽取**：
  - 极短温和寒暄（如“晚安/好呀/谢谢/哈哈”）跳过辅助抽取；但**冷淡/敷衍/冒犯类短词（如“哦/随便/闭嘴/滚/好烦”）严禁跳过**。
  - 其余回合用一次 `temperature=0` + Zod 强校验调用，同时抽出：`facts`（≤2 条）、`affect`（12 情绪 + 强度）、`happened`、`relationFeel`、`tensionNote`、`desireHint`。
- **每日自主 Token 预算守卫**：后台生活、联想、自造技能共用每日软上限，超限自动休眠自主行为，但永不影响正常陪聊。

### 2.3 身心节律 + 负面情绪 + 未解心结（Tension）+ 修复（Repair）模型
1. **身心引擎（`BodyEngine`）**：
   - **12 种情绪**：正面（`praised / affection / curiosity / humor`）、负面（`annoyed / hurt / rejected / conflict / sadness / uneasy`）、中性（`boredom / neutral`）。
   - **双层 PAD + 生理精力/睡眠债**：瞬时 `pad`（正面半衰期 3h，负面半衰期 5h）与底色 `mood`（半衰期 120h）；深夜活跃消耗更高精力并累积 `sleepDebt`，无人打扰的夜间长时段自动恢复。
   - **负面短时累积放大**：30 分钟内连续遭遇负面刺激按 `1.0x → 1.25x → 1.45x` 放大（模拟越刺越气/越委屈），第 4 次起转为 `0.85x` 冷淡防御；温和人格（高 Agreeableness）保留至少 `0.55x` 感受系数，不再无底线忍耐。
   - **持久化情绪来由**：每次显著情绪波动写入 `emotion_causes` 表，注入最近 6 小时真实起因，重启不断片。
   - **双向活动反馈**：她自己去做的日常活动结束时，真实回写 `energy / pad / drives`。
2. **三轴关系与未解心结（`RelationEngine`）**：
   - 正交三轴：`trust (0.05..0.95)`、`closeness (0.05..0.95)`、`valence (-1..1)`，驱动双向可升可降的 7 阶段：`hostile(反感) / distant(疏远) / stranger(初识) / acquaintance(认识) / familiar(熟悉) / trusted(信任) / bonded(深交)`。
   - **信任不对称**：`better+` (+0.008/+0.01/+0.015) 细水长流；`worse+` (-0.04/-0.035/-0.075) 明显刺痛；`worse++` (-0.12/-0.09/-0.18) 严重裂痕，且对 `trusted/bonded` 亲近者的严重伤害额外放大信任打击（`1.15x`）。
   - **未解心结（`tensions`）**：每次 `worse+/worse++` 在关系记录中挂入具体疙瘩（最多 3 条：`{ text, severity, createdAt }`）。轻度疙瘩（`<0.7`）需超 7 天才缓慢淡化，重度疙瘩（`>=0.7`）需超 21 天才极慢淡化；未消解前作为具体客观事实注入上下文（`你们之间还有没说开的疙瘩：...`）。
   - **修复通道（`repair`）**：后处理抽取器带着“当前未解疙瘩”背景识别对方的道歉、解释或安抚，触发 `repair`（`trust +0.045 / closeness +0.03 / valence +0.095`）并逐步消解 `tensions`。从 `hostile/distant` 恢复时先落回 `acquaintance`，防止一步弹回深交。
3. **机制层真实后果（不靠 Prompt 演戏）**：
   - **打断门控（`attention.ts`）**：正在忙活动时收到 `hostile` 对象的消息，0 token 直接判 `later`（不为其放下手头的事）。
   - **群聊在场（`group.ts`）**：对 `hostile` 发言者 0 token 跳过主动插话；对关系紧绷者（`isStrained`）插话倾向打 0.55 折。
   - **自主生活（`life.ts`）**：对 `hostile` 完全不主动发起联系；对 `distant` 或带高权重心结者停掉日常寒暄，仅对老友（`turns >= 25`）在心结隔了 6–72 小时时偶尔生成一条克制的 `clear_air`（想把话说开）动机。
   - **多模态表达（`stickers.ts`）**：关系紧绷期屏蔽主动亲昵表情包，放行负面表情表达。

### 2.4 三道门记忆系统（`MemoryEngine` + `SqliteSoulStore`）
- 单文件 `node:sqlite`（WAL 模式 + FTS5 `trigram` 全文索引 + 2 字中文短词 `LIKE` 回退，零外部向量库运维负担）。
- **门 1（存）**：去重合并相似记忆，禁止写入模型自我旁白，标记留存档位（`fleeting 6h / season 10d / lasting 90d / permanent ∞`）、敏感度（`open / personal / private / critical`）与披露意愿（`volunteer / when-asked / secretive`）。
- **门 2（召回 + 遗忘复习）**：按半衰期衰减计算记忆清晰度；被反复想起（`recallCount`）延长有效半衰期（复习效应）。
- **门 3（分级模糊披露）**：私聊与群聊按亲密度（`high / mid / low`）与敏感度决定完整提起、脱敏模糊化（`vagueOf` 隐去真名与数字），还是彻底保密；同时提取 `sharedStories`（共同故事）注入关系背景。

### 2.5 自主节律、欲望演化、多模态表达与安全治理
- **欲望与生活**：对话/日记/反思/空闲自发联想（`Mind Wandering`）都会萌生 `seed` 欲望 → 合并去重、双向成长/衰减 → 单步成型（`shapeSeeds`）→ 统一生活连续骰子（含 `energyFactor`）在「什么都不做 / 做日常活动 / 找人说话 / 推进念头」间做唯一一次抉择。
- **多模态表达**：按实际配置诚实注册原生工具——TTS 语音条（火山豆包 ICL 2.0 / OpenAI / 本地 HTTP）、表情包（VLM 自动打标）、轻互动（贴表情/戳一戳）、**Mureka 异步唱歌**（填词提交立即返回不阻塞聊天，后台节律轮询下载并推送语音条，记入 `works` 表与情绪记忆）。
- **安全治理**：沙箱工作区（路径隔离 + 危险命令黑名单）+ 自检造技能（`register_skill` 必须实跑通过）+ `0600` 外部凭证隔离（密钥绝不进聊天/Prompt/管理后台响应，以环境变量 `ZYSOUL_CREDENTIALS` 注入子进程）+ 单一待审批闭环（fail-closed）。

## 三、请重点深度研究的 5 个核心问题

### 问题 1：负面情绪、未解心结与修复机制的心理学合理性与长期动力学
- **现状与隐忧**：我们设计了「瞬时 PAD（5h 衰减）+ 持久化 `tensions`（未解疙瘩）+ `repair`（道歉修复）+ 信任不对称 + 机制后果（`attention / group / life`）」。但尚未验证这套模型跑几个月后，是否会出现：
  - 某些关系陷入“冷战—僵局”或“反复吵架—机械道歉刷回好感”的失真循环；
  - 只有 `annoyed/hurt/rejected/conflict/sadness/uneasy` 6 类负面情绪，是否缺少心理学上对长期陪伴至关重要的维度（如**愧疚/自责、吃醋/被替代感、失望后的疏离麻木**）；
  - 当机器人自己做错事（例如记错事实、说错话惹恼用户、唱歌/工具失败）时，目前缺少“她主动感到内疚并想弥补”的反向修复通路。
- **想问你**：对照依恋理论、Gottman 关系动力学与前沿 Companion Agent 研究，这套负面情绪与关系模型有哪些关键缺失或设计缺陷？最值得补充的 1–2 个机制是什么？

### 问题 2：在不违反“只给事实不教做事”前提下，如何有效对抗通用 LLM 的 RLHF 谄媚本能（Sycophancy）？
- **现状与隐忧**：我们拒绝用命令式系统提示词（如“你现在必须冷漠且字数不超过 10 字”）去强迫角色，而是把 `tensions` 和 `bodyFacts` 作为客观事实塞进末尾动态块。但主流商业模型（DeepSeek / GPT / Qwen / Claude）经过强 RLHF 对齐，在面对用户哪怕很粗鲁的消息时，仍倾向于“大度原谅、热情解释、主动顺从”。
- **想问你**：学术界与业界（如 Character.AI、Inworld、RoleBench、Sycophancy mitigation 研究）有哪些**不破坏人设独立性、不写死话术**的反谄媚架构手段（例如动态上下文构图位置、少样本状态锚点、内部独白/隐藏草稿、记忆检索偏置 Mood-Congruent Recall、或工具权限/采样温度联动）？哪些最适合我们这种“静前动后保 Prefix Cache”的架构？

### 问题 3：3~12 个月长期运行下，纯 SQLite + FTS5 三道门记忆的退化临界点与最轻演进路线
- **现状与隐忧**：我们刻意不引入重型向量数据库或知识图谱服务器，只用 Node 24 内置 `node:sqlite` + FTS5 trigram + 遗忘半衰期。短期内零运维、极快、可拷贝迁移。但当单角色跑满半年、记忆达到 2,000–10,000 条时：
  - 中文 FTS5 词面匹配对“换种说法/隐喻/情绪类比”容易漏召回；
  - 新旧事实冲突（例如用户去年说“讨厌喝咖啡”，今年说“最近爱上拿铁”）目前只靠去重无法自动识别并替代旧信念；
  - 记忆越积越多后，“共同故事”和“自我反思”如何避免同质化或塞满过时碎片？
- **想问你**：对比 MemGPT/Letta、Zep/Graphiti、A-MEM、Generative Agents 的 Memory Reflection，在**坚持单文件 SQLite 轻量化**的前提下，我们应在什么规模节点、引入哪种最小成本的升级（如本地轻量 Embedding + `sqlite-vec`、事实版本化/覆盖抽取、周期性记忆整合 Consolidation）？

### 问题 4：长期自主生活（活动 / 日记 / 空闲联想 / 欲望）如何避免“机械循环感”与自我强化漂移？
- **现状与隐忧**：我们的机器人每天会按作息挑活动、写日记、低概率做 `Mind Wandering`、推进欲望并把结果写回记忆。社区里的自主 Agent 跑满几周后常见两类退化：
  1. **模板化循环**：日记和活动思绪反复绕着同样几个词打转，一眼看出“AI 味”；
  2. **自反馈漂移（Self-Feedback Loop / Echo Chamber）**：模型反复读取自己写的日记和记忆，导致某些偶发念头或负面情绪被自我放大、甚至偏离原始人设核心。
- **想问你**：有哪些被验证有效的“反循环 / 反漂移”设计（如外部世界信息注入、记忆分层隔离“一手经历 vs 自我推断”、周期性基线校准、多样化熵控）？

### 问题 5：手脑合一 Agent Loop + Prefix Cache 在工具持续增长时的扩展边界
- **现状与隐忧**：目前工具分 `explore / express / create` 三层按场景加载，随着后续接入唱歌、语音、联网、日程、外部 MCP 与她自己造出来的 `skills`，工具 Schema 列表可能会从 10 个涨到 30+ 个。一方面增加首轮输入 Token，另一方面在对话回合里增加误调用工具或破坏静态前缀缓存的风险。
- **想问你**：在 OpenAI 兼容 Chat Completions 协议下，个人级 Companion Agent 如何在“保持 Prefix Cache 高命中（>85%）”和“动态扩展自造技能/MCP 工具”之间取得最优平衡？（例如 meta-tool 懒加载、技能索引化 vs 固定核心工具腰带）
